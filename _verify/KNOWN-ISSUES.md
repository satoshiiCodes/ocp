# Pre-existing behaviour found while converting, and left alone

These were found by the per-page tests while moving each page's actions and reads
into `actions/<page>-actions.php` and `api/<page>-endpoint.php`. Each one is also
present in `_restructure_backup/`, so none of them was introduced by the
restructure — they are pinned by a test rather than "fixed", because changing
behaviour was not part of the job and the fix might not be what was wanted.

| Where | What happens | Test that pins it |

Admins are unaffected. | `test-report-pages.mjs` checks the login form, a bad-credentials rejection and an empty submission, but does not sign in as a non-Admin, since doing so would need a real password. |

| **RESOLVED — approving or deleting a gasoline PO dumped raw output on the screen** | `api/gasoline_purchase_order-endpoint.php` decided "this is the AJAX lookup" with `array_key_exists('po_id', $_POST)`. **Every form on that page carries a `po_id`** — `approve_po`, `delete_po`, `complete_po`, `update_invoice`, `cancel_po`, `issue_gasoline` — so all of them were answered by the single-PO lookup instead of falling through to the page's listing: the action handlers never ran, and the browser rendered the lookup's answer in place of the page. ## Fixed rather than pinned, because they were regressions

These were introduced by round 1's extraction and had to be repaired:

- **`heavy_equipment.php`** — the edit modal never reopened. The extracted script
  tested `if ($show_edit_modal)`, a page variable that is not in scope in the
  browser's separate request for the script. The flag now travels in the data
  island as `showEditModal`.
- **Five scripts built dropdowns from page variables** — `projects.php`,
  `gasoline_purchase_order.php`, `issue_materials.php`, `purchase_request.php` and
  `pr_view_routing.php` rendered **empty** `<select>` elements, because a `foreach`
  over a page variable iterates over nothing in that separate request. The option
  lists are now rendered by the page (by its endpoint) and handed over in the data
  island.
- **`pr_view_routing.php`** also lost a whole `DOMContentLoaded` handler and left
  its "Create PO" button disabled, from the same cause.
- **`registration.php`** lost `$display_name`, which the side menu prints, so every
  load raised `Undefined variable $display_name`.

`_verify/script-context.mjs` now guards this whole class of bug: it captures each
page's scripts *as the page embedded them* and compares them with the same script
fetched on its own, requiring the two to be identical. It currently reports 26 of
26 identical.
